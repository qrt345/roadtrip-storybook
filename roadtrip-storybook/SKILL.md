# 手绘旅行手账

把用户的行程转换为可分享的单文件HTML。内置纸面、粗线地图、路线棋格、交通标记、目录、键盘/触屏翻页、可关闭动效和本地清单。主题与布局可调；不要固定套用某次旅行的人数、宠物、交通、日期、目的地或12页结构。

## 从资料到页面

读取本次用户指定的有效资料及后续更正，确定权威来源。已有行程就做展示转换；需要新规划时，先形成足够可靠的行程，再制图。按实际内容分成封面、每日路线、重点活动、备选、食宿或清单；没有宠物、汽车、索道时不添加这些安排。

区分“已决定参加”“已经预订”“准入已核实”“时间/价格参考”“尚未安排”。参加活动的确认不能扩展为演出时间或宠物准入的确认。展示转换保留原文的来源日期和不确定性；若新增或更改车程、价格、开放或政策，查询当前来源，未查到就标记未核实。不要为填满模板编造餐厅、酒店或时刻。

为每份行程准备独立工作目录，按 [数据格式](references/data-format.md) 生成 `trip.json`。所有内容字段为纯文本。原始资料若包含精确住址、联系方式、订单或凭证，先制作适合分享的副本，再通过 `source_md` 嵌入；保留与任务无关的原文件。不同旅行使用不同 `id`，避免清单状态混用。

## 地图与动效

地图表达行程拓扑，默认约占桌面页面57%，不用API密钥。`nodes` 是实际安排中的地点，`legs` 明确连接顺序；不要把“二选一”画成连续必去。为备选使用 `choices`，为未执行支路设置 `optional`。

没有可靠经纬度时采用内置棋盘布局，并标注方位与比例为示意。每幅图宜3—7个节点；复杂一天分成几页，避免文字压在道路和建筑上。必要时填写节点 `x/y/dx/dy` 微调，不把示意坐标当经纬度。汽车、步行、索道分别用 `car/walk/cable` 标记；火车和轮船也有独立标记。

内置GSAP及MotionPath，无需再次联网安装GSAP skills、React或Spectrum UI。GSAP核心文件保留版权头；抽屉是原生dialog实现，Spectrum UI交互参考与许可证随包保留。依赖说明见 [使用与分享](references/usage.md)。

## 构建

把 `SKILL_DIR` 替换为本技能实际目录。Python 3.9+，构建只用标准库。

```text
python SKILL_DIR/scripts/build.py --input 工作目录/trip.json --output 输出目录/trip.html
python SKILL_DIR/scripts/build.py --batch 多份数据目录 --out-dir 输出目录
```

批量输入是目录中的JSON文件，每份都先由模型依据资料整理；脚本不使用关键词猜测任意MD内容。构建会预检整个批次、动态生成目录和页数，默认不覆盖既有输出。用户已要求更新同一输出时使用 `--force`；只检查数据可用 `--check`。更新JSON后重建，避免只改单个生成HTML导致下次丢失。

## 验证与交付

至少用浏览器打开实际输出，检查翻页、地图文字、移动端和控制台。确认不同旅行未串用内容或清单，确认路线经过正确节点，动效关闭后仍完整可读。有Python Playwright时，可运行：

```text
python SKILL_DIR/scripts/verify.py --html 输出目录/trip.html --out-dir 验证目录
```

已有系统Edge可加 `--channel msedge`，已有Chrome可加 `--channel chrome`。没有自动化浏览器时使用当前可用浏览器检查，不把文件构建成功报告成视觉验证通过。密集页面允许左侧局部滚动，但关键信息不应裁切；以真实截图决定拆页或缩短。

交付HTML、可继续修改的JSON和必要的来源副本，说明打开方式和实际验证范围。生成本地文件不包含公开发布、预订或联系商家的授权。批量交付说明成功数量和失败项，不笼统声称全部成功。

首次试用可读 [示例数据](assets/examples/coast-weekend.json) 与 [版式预览](assets/preview.png)；它们是明确标注的虚构演示，不是可直接执行的旅游推荐。
